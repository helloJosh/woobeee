# ADR-001. 게시글 목록은 로우 쿼리 기반 오프셋 페이징 + locale별 검색으로 구현한다

- 상태: 적용 (구현 방식 변경: QueryDSL → 로우 쿼리)
- 범위: blog

## 맥락

게시글 목록은 카테고리 필터, 검색어, 다국어(한국어/영어) 본문, 페이징을 동시에 다뤄야 한다. 전역 정책([`../../_global/adr/ADR-001-postgresql.md`](../../_global/adr/ADR-001-postgresql.md))에 따라 커스텀 조회는 로우 쿼리(Native SQL)로 작성하고, 실행 SQL을 코드에서 그대로 읽을 수 있어야 한다.

## 결정

게시글 검색/집계는 **로우 쿼리(Native SQL)** 로 작성한다.

- **동적 조건**: 카테고리 id 집합(`category_id IN (:ids)`)과 검색어 조건을 조건부로 조립한다. 빈 입력은 해당 절을 생략하고, 모든 값은 **바인딩 파라미터**로만 주입한다(문자열 결합 금지).
- **locale별 검색**: `locale = 'en'`이면 `title_en/text_en`, 그 외에는 `title_ko/text_ko`에 대해 대소문자 무시 부분일치(`ILIKE`)로 검색한다.
- **정렬**: `created_at DESC, id DESC` — 동일 생성시각에도 `id`로 tie-break해 페이지 경계가 흔들리지 않게 한다.
- **페이징**: `LIMIT/OFFSET`으로 콘텐츠를 조회하고, 동일 조건의 `COUNT` 쿼리로 total을 구한다.
- **카테고리 집계**: 카테고리별 게시글 수는 `GROUP BY`로 한 번에 구한다(`countGroupByCategoryId`). 빈 입력은 빈 결과로 단락한다.

### N+1 방지

- 목록에 연관 데이터(카테고리·작성자·좋아요 수 등)가 필요하면 **조인으로 한 번에** 조회하거나, 조회된 게시글 id를 모아 **배치(IN) 조회**로 합친다. 게시글마다 단건 조회를 반복하지 않는다.
- 결과는 응답 DTO로 직접 매핑해 지연 로딩을 유발하지 않는다.

## 마이그레이션

- 기존 구현 `PostQueryRepositoryImpl`은 QueryDSL 기반이다. 위 정책에 맞춰 native 쿼리로 교체한다. 교체 후 QueryDSL 의존 제거는 전역 ADR-001의 마이그레이션 항목을 따른다.

## 트레이드오프 / 한계

- 오프셋 페이징은 깊은 페이지에서 비용이 커진다. 데이터가 크게 늘면 커서(keyset) 페이징 전환을 검토한다.
- 별도 `COUNT` 쿼리가 추가로 실행된다.
- 로우 쿼리는 컬럼/테이블명이 스키마와 강하게 결합되므로, 스키마 변경 시 함께 점검한다.
