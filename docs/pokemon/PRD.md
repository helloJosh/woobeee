# pokemon PRD — 포켓코인 공동구매

## 개요

인도 스토어의 포켓코인을 **한 사람이 대신 결제**하고, 친구들은 신청서를 내고 원화로 이체한다.
이 도메인이 하는 일은 셋이다: 신청서를 받고, 이체할 원화 금액을 환율로 확정하고, 진행도를
모두가 볼 수 있게 한다.

- 백엔드: app-mvc `com.woobeee.mvc.pokemon`, 베이스 경로 `/api/back/pokemon`
- **차수(1차·2차·3차) 단위로 연다.** 여는 사람이 그 차수의 주최자이고 URL 이 갈린다:
  `/pokemon` → `/pokemon/{handle}` → `/pokemon/{handle}/{sequence}`
- **통화를 차수가 고른다**(INR/USD/JPY, 설정으로 늘린다). 상품표도 **주최자마다 따로**라
  (주최자, 이름, 통화)가 유일하다 — 스토어가 다르면 가격이 다르고, 주최자끼리 서로의 상품을
  건드리면 안 된다
- **환율을 어떻게 잡을지 주최자가 고른다**: `FIXED`(차수 환율 하나로) 또는 `PER_ORDER`(신청마다)
- **상품표는 운영자가 직접 관리한다** (`/pokemon/products`). 코드가 아니라 DB 에 있으므로
  가격도 구성도 배포 없이 바뀐다. 한때 App Store 의 IAP 목록을 긁었으나, 거기에는 패스가
  `Event Pass Deluxe` 같은 자리표시 이름으로만 떠서 인게임 상점과 맞지 않아 걷어냈다
- 목록에도 없는 것은 루피를 직접 적는다(`extra_inr`)
- 신청서를 저장하면 그 신청서의 세부 페이지로 이동한다 — 저장한 것을 바로 확인할 수 있어야 한다
- **조회는 공개, 쓰는 것은 회원만**이다. 신청·댓글·차수 개설 모두 로그인이 필요하고,
  신청자·작성자 이름은 언제나 회원 닉네임이다 — 누가 냈는지 모르는 신청서는 정산할 수 없다
- 진행 상태를 바꾸는 것만 **운영자**(`pokemon.manager-member-ids`, 기본 `1,3`) 전용이다 —
  블로그의 `ROLE_ADMIN` 과 별개다. 이 공동구매를 실제로 굴리는 사람만 손대야 한다
- 환율은 `open.er-api.com`(키 불필요, **하루 1회 갱신**)을 Redis 로 감싼다. 초 단위 실시간이
  아니고, 그럴 필요도 없다 — 실제 청구액은 카드사 환율 + 해외결제 수수료가 붙어 어차피 달라진다
- 진행도와 환차손익은 **신청서마다** 갖는다. 목록 상단에 평균 진행률이나 환차 합계를 두지 않는다
- 판단 로직(집계·환차손익·가성비·검증)은 `front/lib/pokemon.ts` 에 두고 `lib/pokemon.test.ts`
  가 고정한다. 컴포넌트에는 판단을 두지 않는다

## 인수 기준 (Acceptance Criteria)

| ID | 시나리오 | 기대 결과 |
| --- | --- | --- |
| POKEMON-AC-01 | 상품표 조회 | 6종 고정. 주문 항목에는 **신청 당시 단가**(`unit_price_inr`)를 복사해 저장한다 — 상품표를 고쳐도 과거 신청 금액이 움직이지 않는다 |
| POKEMON-AC-02 | 포켓코인당 단가가 티어 순서대로 싸지지 않는 상품(₹149 = 500포켓코인은 ₹29짜리 100포켓코인 다섯 개 ₹145보다 비싸다) | 상품 카드가 포켓코인당 단가를 그대로 보여주어 고르는 사람이 직접 비교한다. 더 싼 조합을 계산해 권하는 기능은 두지 않았다 |
| POKEMON-AC-03 | 같은 상품을 두 줄로 신청 | 400 + `pokemon_duplicateProduct` — 수량으로 묶는다 |
| POKEMON-AC-04 | 신청서 제출 | 이체액 = `round(루피합계 × 신청시점환율)` + 기부금. 서버는 `BigDecimal.HALF_UP`, 프론트 미리보기는 같은 결과를 내는 `Math.round` |
| POKEMON-AC-05 | 신청 뒤 환율이 움직임 | 신청 행의 `quoted_rate`/`quoted_at` 은 바뀌지 않는다. 이체 금액의 근거이므로 조회 때 다시 계산하지 않는다 |
| POKEMON-AC-06 | 환율 조회 | Redis 신선값(TTL 1시간) → 없으면 외부 조회 → 실패하면 마지막 성공값을 `stale: true` 로 → 그것도 없으면 503 + `pokemon_rateUnavailable`. 환율을 모른 채 추정값을 만들지 않는다 |
| POKEMON-AC-07 | 로그인 필수 | 신청·댓글·차수 개설은 로그인해야 한다(401 + `pokemon_loginRequired`). 신청자·작성자 이름은 요청 값이 아니라 **회원 닉네임**이다 — 남의 이름을 적어 넣을 수 없다. 화면은 비회원이 신청하려 하면 폼을 그리지 않고 로그인으로 보낸다 |
| POKEMON-AC-08 | 진행 상태 | **차수**: `OPEN`(모집중) → `CLOSED`(마감) → `PURCHASED`(구매완료) → `DELIVERED`(배달완료) + `CANCELLED`. **신청서**: `ORDERED`(주문) → `DEPOSIT_CONFIRMED`(입금확인) → `DELIVERED`(전달완료) + `CANCELLED`. 주최자가 전체에 대해 하는 일은 차수가, 개인별로 다른 것(입금)은 신청서가 든다 |
| POKEMON-AC-09 | 운영자가 아닌 사람이 상태 변경 시도 | 403 + `pokemon_managerRequired`. 운영자 여부는 `PokemonProperties.managerMemberIds` 명단으로 판정하고, 화면은 서버가 준 `canManage` 로만 조작 UI 를 그린다 |
| POKEMON-AC-10 | 환율 확정 | 차수가 `PURCHASED` 로 **처음** 넘어갈 때 그 순간 환율이 `settled_rate` 에 박힌다. 되돌렸다 다시 넘어가도 최초 값을 유지한다 — 확정된 손익이 상태를 만질 때마다 움직이면 근거가 못 된다 |
| POKEMON-AC-11 | 환차손익 | **신청서마다** 낸다 — `받아 둔 상품값 − round(루피합계 × 기준환율)`. 기준환율은 확정 건이면 `settled_rate`, 아니면 현재 환율이다. 양수면 남고 음수면 모자란다. **기부금은 섞지 않는다**(환율과 무관한 순수 이득이라 섞으면 환차가 안 보인다). 목록 전체의 환차 합계는 두지 않는다 |
| POKEMON-AC-12 | 신청서 수정·삭제 | 주최자는 언제든. 그 밖에는 **본인이 낸 것**만이고 입금이 확인되기 전(`ORDERED`)까지다. 주인이 없는 신청서(회원 전용으로 바꾸기 전 비회원이 낸 것)는 본인 확인이 성립하지 않아 주최자만 손댄다 |
| POKEMON-AC-13 | 신청서 댓글 | 누구나(비회원 포함) 달 수 있다. 삭제는 운영자이거나 본인이 쓴 댓글만 — 작성자 회원 id 를 내보내지 않고 서버가 `mine` 으로 판단해 내려준다 |
| POKEMON-AC-14 | 오류 코드 | `PokemonErrorCode` 와 `front/lib/errors/error-messages.ts` 의 ko/en 이 **양방향으로** 일치한다. 지도에 없는 코드도, 코드 없는 지도 키도 실패다 |
| POKEMON-AC-15 | 신청서 응답 | 받아 가는 코인 총합(`totalCoins`)을 함께 내려준다. 화면은 항목에서 다시 세어 쓴다 — 표의 항목과 합계가 같은 출처에서 나와야 어긋나지 않는다 |
| POKEMON-AC-16 | 목록 집계 | 목록이 내는 합계는 상태별 건수, 총 포켓코인, 미입금(= 입금확인 전) 명단·금액, 배달 완료 전 금액뿐이다. **진행도와 환차손익은 합치지 않는다** — 둘 다 신청서마다 보여준다 |
| POKEMON-AC-17 | 진행도 | **신청서마다** 갖는다 — 네 단계 중 몇 번째인지. 신청만 한 상태도 `1/4` 로 센다(갓 낸 신청서가 0% 로 비어 보이면 안 된다). 취소는 진행 경로 밖이라 `null` 이고 0 이 아니다. 목록 전체의 평균 진행률은 두지 않는다 |
| POKEMON-AC-18 | 운영자 화면 | 운영자에게만 **배달 완료 전** 신청서의 집계를 보여준다 — 건수, **루피 합계**(인도 스토어에서 실제로 써야 할 돈), **기부금 뺀 원화**(상품값만), 이체 합계(기부금 포함), 미입금 건수·금액, 총 포켓코인. 취소는 처리할 것이 없으므로 뺀다 |
| POKEMON-AC-19 | 자유 입력 루피 | 상품표에 없는 것(프리미엄 패스 등)을 위해 루피를 직접 적을 수 있다. 소수 둘째 자리까지 허용하고(스토어 가격이 `₹29.00` 꼴이다) 음수는 거절한다. `total_inr` 에 더해지되 `extra_inr` 로 따로 보관한다 — 항목 단가 스냅샷과 섞으면 "무엇을 얼마에 샀는가" 가 흐려진다. **상품을 하나도 고르지 않아도 루피만 있으면 유효한 신청**이고, 둘 다 비면 400 + `pokemon_emptyOrder` 다. 포켓코인 수는 상품에서만 나온다 |
| POKEMON-AC-20 | 상품 관리 | 상품표는 운영자가 화면(`/pokemon/products`)에서 직접 넣고 고친다. 패스는 달마다 바뀌고("GO패스 디럭스: 9월") App Store 의 IAP 목록에는 그 이름이 뜨지 않아 자동으로 가져올 수 없다 |
| POKEMON-AC-21 | 상품 내리기 vs 지우기 | 신청서에 쓰인 상품은 **지울 수 없다**(400 + `pokemon_productInUse`). 내리면(`active=false`) 신청 화면에서만 빠지고 과거 신청서는 그대로 읽힌다. 쓰인 적 없는 상품만 지워진다 |
| POKEMON-AC-22 | 내려간 상품 신청 | 비활성 상품이나 없는 id 로 신청하면 404 + `pokemon_productNotFound`. 가격은 요청이 아니라 상품표에서 읽는다 — 클라이언트가 보낸 금액은 믿지 않는다. 상품 가격을 고쳐도 **과거 신청서는 움직이지 않는다**(항목이 당시 단가를 스냅샷으로 들고 있다) |
| POKEMON-AC-23 | 신청서 수정 | 항목·기부금·자유 루피·메모를 **전체 교체**한다. 금액은 **수정 시점 환율**로 다시 계산되고 `quoted_rate`/`quoted_at` 도 함께 갱신된다 — 주문 내용이 바뀌면 이체할 금액도 바뀌므로 옛 환율이 더 이상 근거가 아니다. `settled_rate` 는 건드리지 않는다(이미 결제한 건의 확정 손익은 나중에 고쳤다고 움직이면 안 된다). 권한은 삭제와 같은 규칙이다 |
| POKEMON-AC-24 | 상품 입력 검증 | 이름 필수(200자), 루피는 0보다 큰 수(소수 둘째 자리까지), 포켓코인은 0 이상 정수(패스·티켓은 0, 빈 값도 0) |
| POKEMON-AC-25 | 차수 개설 | 로그인해야 하고, 먼저 주소(`handle`)를 정해야 한다(400 + `pokemon_hostRequired`). 차수 번호는 주최자 안에서 1부터 자동으로 매겨진다 |
| POKEMON-AC-26 | 주최자 주소 | 소문자·숫자·하이픈만(400 + `pokemon_invalidHandle`), 이미 쓰는 주소면 거절(400 + `pokemon_handleTaken`). 회원당 하나이고 바꾸면 이전 주소가 죽으므로 한 번만 정한다 |
| POKEMON-AC-27 | 차수 환율 | 주최자가 `FIXED`/`PER_ORDER` 를 고른다. `FIXED` 면 차수 환율로 전부 계산하고, 주최자가 값을 고칠 수 있지만 **이미 들어온 신청서는 각자 박아 둔 환율을 유지한다** — 알려 준 이체 금액이 나중에 달라지면 안 된다. 통화는 바꿀 수 없다 |
| POKEMON-AC-28 | 차수 범위 | 신청은 **모집중**인 차수에만 받는다(400 + `pokemon_roundClosed`). 담을 수 있는 상품은 **그 차수 주최자의, 그 차수 통화의, 살아 있는 것**뿐이다(404 + `pokemon_productNotFound`) |
| POKEMON-AC-30 | 주최자 기본 계좌 | 상품 관리에서 기본 입금 계좌를 정해 두면 차수를 열 때 자동으로 채워진다. 차수는 계속 자기 계좌를 따로 들고 있어서 **기본값을 고쳐도 이미 연 차수는 바뀌지 않는다** — 그 계좌로 이미 입금한 사람이 있다. 둘 다 없으면 400 + `pokemon_bankAccountRequired` |
| POKEMON-AC-29 | 차수 권한 | 차수를 주무르는 것은 그 차수의 주최자 또는 전역 운영자뿐이다(403 + `pokemon_notTheHost`). 신청서가 있는 차수는 지울 수 없다(400 + `pokemon_roundHasOrders`) — 취소 상태로 둔다 |
| POKEMON-AC-31 | 차수 상품표 | 상품표는 **차수마다** 갖는다. 내 상품표는 틀이고, 차수를 열 때 그 통화의 것을 복사해 심는다. 그 뒤로 둘은 서로 영향을 주지 않는다 — 다음 달 패스로 틀을 고쳐도 이미 닫힌 차수의 목록은 그대로다. 담을 수 있는 것은 그 차수 상품표의 살아 있는 상품뿐이다 |
| POKEMON-AC-32 | 폴더 카드와 페이징 | 차수 화면 위에 그 주최자의 차수들이 폴더 카드로 늘어서고, 누르면 그 차수로 간다(주소가 유지되어 링크를 공유할 수 있다). 신청서 목록은 한 페이지에 10건이고, 빈 목록도 1페이지이며 범위를 벗어난 페이지는 끝으로 당긴다 |
| POKEMON-AC-33 | 차수 관리 화면 | 주최자는 `/pokemon/{handle}/{n}/manage` 에서 그 차수의 환율·계좌·마감일과 **그 차수의 상품표**를 고친다. 통화는 못 바꾸고, 환율을 바꾸면 앞으로의 신청서에만 적용된다. 틀에서 복사해 올 수 있고 이미 있는 이름은 건너뛴다 — 차수에서 고친 가격을 틀이 덮으면 안 된다 |
| POKEMON-AC-34 | 주최자 방 | `/pokemon/{handle}` 은 차수를 **탭**으로 나눈다. 고르면 그 차수 화면이 **그 자리에** 뜨고, 아무것도 고르지 않으면 가장 최근 차수를 연다. 고른 탭은 `?round=N` 으로 주소에 남아 링크를 공유할 수 있고, `/pokemon/{handle}/{n}` 은 그리로 보낸다 — 차수 본문을 두 곳에서 그리면 언젠가 어긋난다 |
