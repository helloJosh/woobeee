# 할 일 시간 입력과 시작 전 Slack 알림 — 설계

2026-09-04. `docs/superpowers/specs/2026-09-01-schedule-tab-design.md` 의 확장. 할 일에만 적용한다.

## 1. 결정

| 갈림길 | 선택 | 이유 |
| --- | --- | --- |
| 시간 저장 | `tasks` 에 `start_time TIME NULL`, `end_time TIME NULL` **추가**. 날짜 컬럼은 그대로 | 달력 배치·자동 완료·다이제스트가 전부 `start_date`/`end_date` 로 돈다. 시간은 선택 입력이라 기존 행·쿼리가 그대로 유효하다. `TIMESTAMP` 교체는 "종일" 플래그가 따로 필요하고 프론트의 `"YYYY-MM-DD"` 비교 로직을 전부 다시 써야 한다 |
| 알림 저장 | 별도 테이블 `task_reminders (task_id, minutes_before ∈ {10, 30}, sent_at)` | 발송 여부를 행에 남겨야 재시작 후 중복 발송을 막는다. 불리언 컬럼 둘로는 "보냈는지"를 못 기록한다 |
| 알림 채널 | 멤버별 Slack webhook (기존 `members.slack_webhook_url`) | 다이제스트와 같은 배선. 브라우저를 꺼도 온다 |
| 적용 범위 | 할 일만 | 프로젝트·마일스톤은 기간 단위 |

## 2. 데이터

`V11__task_time_reminders.sql`

```sql
ALTER TABLE tasks ADD COLUMN start_time TIME, ADD COLUMN end_time TIME;
CREATE TABLE task_reminders (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    task_id BIGINT NOT NULL,
    minutes_before INT NOT NULL CHECK (minutes_before IN (10, 30)),
    sent_at TIMESTAMP(6),
    UNIQUE (task_id, minutes_before)
);
```

FK 없음 — 다른 schedule 테이블과 같이 서비스 계층이 캐스케이드를 명시적으로 수행한다
(할 일·마일스톤·프로젝트 삭제 시 `task_reminders` 먼저).

## 3. API (`/api/back/schedule/tasks`)

요청(`POST`/`PUT`)과 응답, 트리의 `TaskNode` 에 세 필드가 늘어난다.

| 필드 | 타입 | 규칙 |
| --- | --- | --- |
| `startTime`, `endTime` | `"HH:mm"` 또는 null | 해당 날짜가 null 이면 시간도 null 로 정규화한다. 같은 날짜에 둘 다 있으면 `endTime >= startTime`, 위반 시 `schedule_invalidDateRange` |
| `reminders` | `number[]` (기본 `[]`) | 값은 10·30 만 — 아니면 `schedule_invalidReminder`. 비어 있지 않은데 `startDate` 나 `startTime` 이 없으면 `schedule_reminderNeedsStartTime` |

`PUT` 은 알림 집합을 통째로 교체한다. **시작 일시와 집합이 모두 같으면 행을 건드리지 않아**
이미 보낸 알림이 다시 나가지 않는다. 하나라도 다르면 삭제 후 재생성(`sent_at` 리셋).

## 4. 발송 — `TaskReminderNotifier`

- `@Scheduled(fixedDelay = 60_000)`. 기준 시각은 다이제스트 cron 과 같은 `Asia/Seoul` 의 `LocalDateTime.now()` 를 Java 에서 넘긴다.
- 네이티브 쿼리 한 번(`TaskReminderRepository.findDue(now)`): `task_reminders ⋈ tasks ⋈ members ⟕ projects`,
  조건 `sent_at IS NULL AND start_date·start_time NOT NULL AND slack_webhook_url NOT NULL AND
  (start_date + start_time) - minutes_before ≤ now < (start_date + start_time)`.
  즉 서버가 죽어 있다 살아나면 **이미 시작한 할 일의 알림은 건너뛴다**.
- 건마다 `send` 성공 후 `markSent(id, now)`. 실패는 로그만 남기고 다음 건으로 (AC-27 과 동일).
  실패한 건은 `sent_at` 이 그대로라 다음 분에 재시도되고, 시작 시각을 넘기면 자연히 빠진다.
- 본문은 `TaskReminderFormatter` 순수 함수: `⏰ 30분 후 시작 (14:30) — [DM] 회의`, 무소속은 접두 없이.

## 5. 프론트

- `ScheduleTask` 에 `startTime`, `endTime`, `reminders`. 판단은 `lib/schedule.ts`:
  `REMINDER_OPTIONS`, `isValidTimeRange`, `canRemind`, `formatTaskRange`, `taskPutBody`.
- 할 일 다이얼로그: 날짜 옆에 `<input type=time>`(날짜가 비면 비활성), 아래 "시작 전 알림" 체크박스 10분·30분
  (`canRemind` 가 거짓이면 비활성 + 이유). Slack 미등록이면 발송되지 않는다는 안내.
- 날짜만 편집하는 곳(막대 팝오버·막대 드래그·배지 클릭)은 `PUT` 이 전체 교체라서 `taskPutBody` 로
  기존 시간·알림을 실어 보낸다 — 여기가 놓치기 쉬운 지점이라 테스트로 고정한다.
- 트리 행과 달력 막대 라벨에 시간이 있으면 표시.
